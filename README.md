# 校园食堂餐券双账结算

按流水核对餐券核销与退扣，复核各校区和档口组的应结金额。

青禾大学后勤餐饮中心，每日与东西两个校区的自营及合作档口结算餐券。 校园卡中心导出餐券账，食堂收银系统导出核销账。后勤结算员原先用表格查流水并统计档口应结金额，现在将两份账合并为带来源列的 CSV，由系统逐笔核对。食堂值班员按流水回查原单，财务复核员使用勾稽表确认涉账校区和档口组后安排划款。

- 收银离线补传会导致一侧暂缺流水，汇总金额看不出缺的是哪张餐券。
- 隔日退扣与整笔冲正需要追到原核销流水，单看金额很难发现扣错原单。
- 两笔差额可能相互抵消，同额挂错校区也会影响档口结算。

## 业务模块

| 模块 | 用途 |
|---|---|
| 结算总览 | 查阅业务口径、当班流程及最新运行。主管可以核对审计记录。 |
| 双账明细 | 下载「青禾大学餐券双账_20261119-20.csv」并核对字段。分析员可导入 UTF-8 CSV，保留数据指纹和原始行。 |
| 日终清分 | 选择批次和参数并提交后台计算，可从运行列表追踪状态。 |
| 清分结果 | 查看业务指标、证据表和解释，通过来源链接回查数据。 |
| 结算复核 | 查看待处理或已完成记录。复核主管可提交结算复核及依据。 |
| 结算交付 | 按批查找结果，核对复核状态并下载相应的 CSV。 |

## 演示流程

1. 11 月 20 日 20:30，合并校园卡中心和食堂收银记录，生成「青禾大学餐券双账_20261119-20.csv」。
2. 在「双账明细」导入 20 行，保留 11 月 19 日的三笔核销双账供隔日退扣回查。
3. 在「日终清分」选择 11 月 20 日，核对当天两账共 14 行，覆盖 8 个流水号。
4. 在「清分结果」查看 3 笔匹配、2 笔单边缺失和 3 笔差异，并核对两账净额 3070 分和 3080 分。
5. 在「结算复核」按流水 C006 查补传，按 C008 核对校区归属，按 P002 核对退扣单据。
6. 改查 11 月 19 日，确认三笔原核销全部匹配，两账均为 2900 分，结算检查通过。
7. 在「结算交付」下载清分报告，将检查通过的批次交给财务。

## 计算口径

- 同一来源内流水号唯一，同一流水号可在两个来源各出现一次。按入账日选取流水，比较类型、原核销号、校区、档口组和金额。
- 输入金额为大于零的整数分。净额等于核销金额减去部分退扣及全额冲正。隔日调整须在同一账内引用原核销，校区和档口组沿用原单。
- 同一原单累计部分退扣须小于原金额。全额冲正最多一笔，金额等于扣除截至冲正日的部分退扣后所余金额，冲正日后禁止再退扣。
- 各账按自身校区与档口组归集，交叉表分别与原始行计算的校区、档口组和全账合计勾稽。差额统一为校园券账减食堂核销账。
- 存在入账记录、双账无缺失和差异且勾稽成立时才通过结算检查。单笔异常即使在汇总中抵消，仍会阻断结算。

## 本地开发

| 组件 | 实现 |
|---|---|
| 前端 | Nginx 与原生 HTML、CSS、JavaScript。`frontend/src/pages` 放页面，`components/common` 放共用表格、图表及表单。 |
| API | Python 3.11、FastAPI、SQLAlchemy。`backend/src/domain` 放本项目字段、业务计算和演示数据，`routes` 放接口，`models` 放表模型。 |
| 后台 | 独立 Python worker，通过 Redis 唤醒，从数据库租约领取计算，CSV 写入共享卷。 |
| 数据 | PostgreSQL 16 存储批次、运行与审计。`backend/scripts/seed_demo.py` 可安全重复执行。 |

改动前端后执行 `docker compose up -d --build frontend`。改动接口或算法后执行 `docker compose up -d --build backend worker`，再刷新浏览器。如需保留数据，停止时执行 `docker compose down`。使用 `docker compose down -v --remove-orphans` 会清除该项目的数据库、Redis 和报表卷。

`.env.example` 中的 `COMPOSE_PROJECT_NAME`、`FRONTEND_PORT`、`BACKEND_PORT`、`DB_PORT`、`APP_SUBNET` 控制项目隔离。`DB_PASSWORD`、`JWT_SECRET` 和 `SEED_DEMO` 为本机演示默认设置。后端 `constants/enums.py` 与前端 `src/constants/enums.js` 保持角色、运行状态和复核状态一致。项目许可证见 `LICENSE`。
